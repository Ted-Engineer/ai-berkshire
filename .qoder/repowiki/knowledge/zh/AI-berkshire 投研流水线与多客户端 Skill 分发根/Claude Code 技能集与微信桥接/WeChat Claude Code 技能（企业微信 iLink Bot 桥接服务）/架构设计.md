以 `src/main.ts` 为唯一入口，提供 `setup`（扫码绑定账号并持久化到 `wechat/accounts.ts`）和 `daemon`（常驻进程）两种运行模式；daemon 启动后通过 `wechat/monitor.ts` 轮询 iLink 事件，按优先级先处理 `/stop`、`/clear` 等中断命令，其余消息进入串行队列经 `commands/router.ts` 路由：斜杠命令由 handlers 直接回复或触发 Claude 查询，普通消息则调用 `claude/provider.ts` 子进程发起流式请求，经 `claude/turn-router.ts` 解析 NDJSON 流并按 role 区分 interstitial/final，再通过 `tool-noise-filter.ts` 压缩工具日志噪声后交由 `wechat/send.ts` 分块推送回微信；会话状态、聊天历史、SDK session ID 统一由 `session.ts` + `store.ts` 持久化，`pending-queue.ts` 在微信侧限频时暂存未送达的响应片段并在下次用户消息携带新 context_token 时自动补发，`config.ts` 集中管理工作目录、系统提示词等配置，`logger.ts` 贯穿所有子模块输出结构化日志。
