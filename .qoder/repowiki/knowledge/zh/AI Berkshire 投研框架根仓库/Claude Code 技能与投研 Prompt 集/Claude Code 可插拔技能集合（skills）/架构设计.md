模块采用扁平的 `skills/<skill-name>/` 目录组织，每个子目录是一个自包含技能单元，依赖方向单向：上层 Agent 通过名称解析并加载对应技能，技能之间不直接 import，仅通过约定（如 `/grilling`、`/research`、`/wayfinder` 等斜杠命令）松耦合协作。
- 入口契约：每个技能根目录的 `SKILL.md` 使用 YAML front-matter（`name`、`description`、可选 `disable-model-invocation`、`allowed-tools`、`version`）声明元数据，正文即结构化提示词/工作流规范。
- Agent 配置：每个技能 `agents/openai.yaml` 描述 `display_name`、`short_description` 及模型/工具绑定，使同一份提示词可在不同运行时切换后端。
- 扩展结构：复杂技能将辅助文档拆分为独立 Markdown（如 `codebase-design/DESIGN-IT-TWICE.md`、`domain-modeling/ADR-FORMAT.md`、`open-websearch/references/*.md`），由主 SKILL.md 通过相对路径引用；需要外部交互的技能在 `scripts/` 下放置 shell 模板或守护脚本（如 `diagnosing-bugs/scripts/hitl-loop.template.sh`、`git-guardrails-claude-code/scripts/block-dangerous-git.sh`、`wechat-claude-code/scripts/daemon.sh`）；`wechat-claude-code/` 是完整 Node.js/TypeScript 子项目，含 src/、tests、package.json，作为独立可安装的二进制被 SKILL.md 调用。
- 顶层 Markdown 文件（如 `bottleneck-hunter.md`、`daily-brief.md`、`thesis-tracker.md` 等）是无需 agent 配置的纯文本技能，直接作为提示词被加载。
