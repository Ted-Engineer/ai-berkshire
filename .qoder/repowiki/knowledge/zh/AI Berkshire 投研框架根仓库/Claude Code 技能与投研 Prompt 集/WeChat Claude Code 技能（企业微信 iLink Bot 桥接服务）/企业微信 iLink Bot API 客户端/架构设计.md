模块以 `api.ts` 中的 `WeChatApi` 类为核心，封装所有对 `https://ilinkai.weixin.qq.com/ilink/bot/*` 的 POST 请求（getUpdates/sendMessage/getConfig/sendTyping/getUploadUrl），并通过内部 `request` 方法统一注入 Bearer Token、AuthorizationType、X-WECHAT-UIN 头与超时控制。

围绕该核心按职责拆分为多个子文件：
- 认证与会话：`login.ts` 实现两步 QR 扫码登录（获取二维码 + 轮询状态），成功后通过 `accounts.ts` 将 `AccountData`（botToken、accountId、baseUrl、userId）持久化到 `~/.wechat-claude-code/accounts/*.json`；`sync-buf.ts` 用 `store.js` 在 `DATA_DIR/get_updates_buf` 中持久化长轮询的 `get_updates_buf`。
- 消息收发：`send.ts` 通过工厂函数 `createSender` 暴露 `sendText`/`sendFile`/`startTyping`，其中 typing 指示器带 ticket 缓存（TTL 24h）和 keepalive 循环；`media.ts` 负责从 `MessageItem` 中提取 CDN 信息并下载解密为 data URI 或临时文件。
- 媒体上传：`upload.ts` 调用 `getUploadUrl` 后使用 AES-128-ECB（`crypto.ts`）加密文件，POST 到 CDN 并读取响应头 `x-encrypted-param` 作为下载凭证。
- 下载解密：`cdn.ts` 根据 `encrypt_query_param` 构造下载 URL，支持两种 aesKey 编码格式（base64-of-raw / base64-of-hex）并解密。
- 监控与容错：`monitor.ts` 的 `createMonitor` 启动无限循环调用 `getUpdates`，实现消息去重（最近 1000 条 message_id）、会话过期（ret:-14 暂停 1h）、指数退避重试；`api.ts` 内建熔断器（circuit breaker）针对 ret:-2 限流，首次命中即打开 30s 窗口快速失败，避免生产环境“撞墙”循环。

依赖方向单向向下：`send`/`monitor` → `api` → `crypto`/`cdn`；账户与同步缓冲通过共享的 `store.js` 与 `constants.js` 访问磁盘，模块本身不持有全局状态。
