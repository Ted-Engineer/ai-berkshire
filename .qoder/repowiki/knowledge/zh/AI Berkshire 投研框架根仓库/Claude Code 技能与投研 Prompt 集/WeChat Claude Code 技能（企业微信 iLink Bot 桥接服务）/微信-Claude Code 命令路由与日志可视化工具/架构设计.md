模块由两个相对独立的子部分组成：
- `src/commands/`：命令子系统入口。`router.ts` 定义 `CommandContext` / `CommandResult` 接口并通过 `switch` 将 `/help`、`/clear`、`/model`、`/status`、`/skills`、`/history`、`/undo`、`/compact`、`/send`、`/prompt`、`/version` 等斜杠命令分派到 `handlers.ts` 中的对应处理器；未知命令回落到 `handleUnknown`，尝试匹配已安装的 Claude Skill（通过 `claude/skill-scanner.js`）。`handlers.ts` 仅依赖配置、会话持久化与文件系统，不直接调用 WeChat API。
- `src/tools/visualize-logs.ts`：独立 Node CLI（`#!/usr/bin/env node`），通过 `WCC_DATA_DIR` 读取 `logs/bridge-YYYY-MM-DD.log`，按 `Starting`/`Claude query completed`/`API sendmessage` 等日志行重建会话，再结合 `sessions/*.json` 中的 `chatHistory` 注入 Claude 完整输出，用字符级 diff 算法对比“Claude 原始输出”与“实际发送到微信的消息”，最终生成自包含 HTML 页面供浏览器查看。
- 与上层集成：`main.ts` 在消息进入时构造 `CommandContext` 并调用 `routeCommand`，根据返回的 `reply`/`claudePrompt`/`sendFile` 字段决定回复文本、转发给 Claude 或发送文件；`tools/visualize-logs.ts` 则完全脱离运行时，仅依赖磁盘日志与 session JSON。
